## Ringkasan dengan bahasa sederhana

Alur FCFS sudah tersedia dalam kode. Pengguna mengisi daftar proses, lalu
browser mengirim datanya ke Python. FCFS mengurutkan proses berdasarkan waktu
kedatangan dan melayani masing-masing sampai selesai. Python mengembalikan
urutan pengerjaan dan angka hasilnya; browser menggambarkannya sebagai Gantt
chart dan tabel.

Namun, tampilan saat ini meminta semua algoritma sekaligus. Belum ada alur
antarmuka khusus yang sederhana untuk memilih FCFS saja. Ini temuan dari
kode, bukan hasil pengamatan browser.

## Detail FCFS yang perlu dipahami

- Arrival berarti waktu proses datang; burst berarti lama pekerjaan CPU.
- CPU dalam model ini mengerjakan satu proses sampai selesai sebelum beralih.
- Jika dua proses datang bersamaan, implementasi mengurutkan nama sebagai teks.
  Nama `P10` dapat mendahului `P2`; aturan ini perlu dinyatakan, bukan dianggap
  otomatis mengikuti urutan pengguna memasukkan baris.
- Jika belum ada proses yang datang, segmen `IDLE` berarti CPU sedang kosong.
- Waktu selesai diambil dari akhir segmen terakhir proses.
- Turnaround = waktu selesai dikurangi waktu datang.
- Waktu tunggu = turnaround dikurangi burst.
- Response = waktu pertama mulai dikerjakan dikurangi waktu datang.
- Dalam fungsi FCFS, `context_switches` dihitung sebagai jumlah segmen proses
  selain IDLE dikurangi satu, dengan minimum nol. Ini definisi hitungan model;
  kode FCFS tidak menambahkan durasi biaya perpindahan proses.
- Tabel metrik diurutkan menurut nama proses oleh `build_metrics()`. Urutan
  baris tabel tersebut tidak selalu sama dengan urutan eksekusi pada Gantt chart.

## Pemeriksaan yang benar-benar dilakukan

Semua pemeriksaan di bawah dilakukan pada 24 Oktober 2026 dan selesai dengan
exit code 0. Ini keberhasilan membaca/mencari teks, bukan hasil tes aplikasi.

1. Membaca aturan, rencana, status, kontrak T01 dan template hasil menggunakan
   `Get-Content -LiteralPath ... -Encoding UTF8`.
2. Mencari lokasi fungsi dengan `rg -n`, termasuk perintah berikut:

   ```powershell
   rg -n 'scheduling|def |ROUTES|do_POST|_json|Content' src/server.py
   rg -n '<script' web/index.html
   ```

   Hasil: endpoint `api_scheduling` ditemukan di baris 56 dan rute di baris
   235; script util, scheduling dan app tercantum pada HTML.
3. Membaca `web/js/scheduling.js` dan `src/scheduling/models.py` dengan nomor
   baris; membaca awal `algorithms.py` untuk FCFS, serta bagian registry dan
   `compare_all()` untuk hubungan pemanggilan saja.
4. Membaca HTML untuk form scheduling, awal server untuk validasi scheduling,
   `do_POST()` dan `_handle_api()` untuk jalur request, serta `util.js` dan
   `app.js` untuk pengiriman dan inisialisasi halaman.

Tidak dilakukan audit algoritma Round Robin, Producer–Consumer atau deadlock.
Nama/cabang fitur lain terlihat pada kode bersama, tetapi bukan objek penilaian T01.
