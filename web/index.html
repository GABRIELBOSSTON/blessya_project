CPU Scheduling: FCFS and Round Robin

CPU scheduling determines the order in which processes are executed by a single CPU. FCFS (First Come First Served) executes processes in arrival order until completion, while Round Robin shares CPU time in turns with a fixed time slice called quantum.

1

Simulation configuration

Non-preemptive: processes are executed to completion in arrival order.

Maximum duration of one execution turn (1–20 time units).

Arrival: time the process enters the queue. Burst: CPU time required by the process.

ProcessArrivalBurstDelete

Maximum 12 processes. Arrival 0–100 and burst 1–50, in simulation time units.

Model assumptions

The model uses a single CPU without I/O operations, and context switch time is not accounted for. Processes with the same arrival time are ordered lexicographically by name (e.g. P10 before P2).

In Round Robin, processes arriving up to the end of a time slice are enqueued first before the preempted process is re-enqueued at the back. The name IDLE is reserved to indicate an idle CPU.

Producer–Consumer: Bounded Buffer

A classic synchronization problem: producer threads store items into a bounded buffer, while consumer threads retrieve them. Semaphores control when each thread must wait, and a mutex ensures the buffer is modified by only one thread at a time.

1

Simulation configuration

The simulation uses one producer thread and one consumer thread.

The ms values are requested delays, not guaranteed times. OS thread scheduling may add variance, so results may differ between runs.

Synchronization mechanism

Semaphore empty counts empty slots; the producer waits when its value is zero. Semaphore full counts available items; the consumer waits when its value is zero. Mutex ensures buffer modifications are done by one thread at a time.

The simulation uses real threads within a single Python process with shared memory. What is demonstrated is a classic synchronization problem, not communication between two separate OS processes.
